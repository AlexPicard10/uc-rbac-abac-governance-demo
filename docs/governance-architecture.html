UNITY CATALOG · RBAC + ABAC

One policy, two domains — access decided by your active role

Synthetic demo · generation + district-heating · AWS

1 · RBAC — assumable roles

Users join a member group that may ASSUME a role. Assuming a role replaces the session's permissions with the role's (one active role at a time).

generation_users → role_generation heating_users → role_heating cross_domain_users → role_cross_domain

2 · ABAC — governed tag + 1 policy

A governed tag marks country_code, so one catalog-scoped row-filter policy protects both tables. Which rows each role sees comes from an entitlement table keyed on the active role (session_user()): domain roles = all; cross-domain = FR + BE.

GOVERNED TAG country ROW FILTER ← entitlement table (cross-domain = FR+BE)

3 · Genie — same rules

Genie writes & runs SQL as the asking user, so the active role's grants and the ABAC filter apply. Genie never bypasses Unity Catalog.

Space: Generation Space: Heating Cross-domain: Genie One CAN_RUN ≠ data access

4 · Ontology — certified KPIs

KPIs defined once in certified metric views (queried with MEASURE()) over a sites dimension with PK/FK relationships and rich comments. The dashboard and Genie One reuse the same governed measure, which inherits the base-table row filter (cross-domain KPIs = FR + BE).

generation_metrics · heating_metrics asset_reference (sites PK/FK) system.certification_status = certified

Grant once · enforced everywhere · provable in SQL. Member groups hold no data grants — only the right to assume a role. The filter uses session_user() (the role name), not is_account_group_member() — a role is not a member of itself. All data is synthetic.
